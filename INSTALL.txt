mcqsgenerator.com/tool — deployment in short
============================================

The full guide is HOSTINGER-GUIDE.md (or docs/hostinger-deploy.md). This is the
condensed version for the Git deployment route.

This repository IS the site. Hostinger pulls it into public_html/tool and
redeploys on every push to main.

ONE-TIME SETUP
--------------
1. hPanel -> Advanced -> PHP Configuration
   PHP 8.2, enable pdo_mysql, mbstring, openssl, fileinfo, gd.
   memory_limit 256M, max_execution_time 120.

2. hPanel -> Databases -> MySQL Databases
   Create the database and its user. Host is "localhost".
   Note the generated name, user and password.

3. hPanel -> Advanced -> Git -> Connect with GitHub
   Repository : laheef/tools-mcqsgenerator
   Branch     : main
   Root dir   : public_html/tool        <- must be EMPTY or not exist yet
   Click Deploy.

   Do NOT extract a zip into public_html/tool first; the deploy fails if the
   folder already has files in it.

4. phpMyAdmin -> select the database -> Import -> tool/install/database.sql
   It creates the tables and the content. It contains no user account.

5. Open https://mcqsgenerator.com/tool/admin/install.php
   Enter the database details from step 2, then your own admin e-mail/password.
   It writes config.db.php and creates your account.

6. Download public_html/tool/config.db.php and keep it safe. It is git-ignored,
   so Git can never restore it for you.

7. Force HTTPS in hPanel, pick www or non-www.

UPDATES FROM NOW ON
-------------------
   git clone https://github.com/laheef/tools-mcqsgenerator.git
   cd tools-mcqsgenerator
   # edit
   git add -A && git commit -m "..." && git push origin main

   Hostinger redeploys automatically (hPanel -> Git -> All deployments shows the
   commit). If the change needs a schema update, the admin dashboard shows an
   "Upgrade" button - click it once.

RULES
-----
* Never edit tracked files on the server; the next deploy overwrites them.
  Site content goes through the admin panel, code goes through a commit.
* Do not delete install/ or admin/install.php: Git restores them. They are
  already blocked (403) and the installer locks itself after setup.
* Never commit config.db.php, data/backups/*.sql or uploads/media/*.
* Bump ASSET_VERSION in config.php whenever you change CSS or JS.

CHECKS AFTER THE FIRST DEPLOY
-----------------------------
  /tool/                    4 041 calculators, styled
  /tool/math/percentage     25 + 200 -> Calculate -> 50
  /tool/biology/dog-age     calculates
  /tool/sitemap.xml         4 065 URLs, all under /tool/
  /tool/robots.txt          Allow: /tool/ , Disallow: /tool/admin/
  /tool/admin/              sign-in form
  /tool/config.db.php       403 or 404, never the contents
  /tool/.git/config         403  <- proves the history is not downloadable
  /tool/install/            403
